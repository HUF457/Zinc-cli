# Zinc 0.6.9

Zinc is a **lightweight multi-shell Windows terminal launcher**: vertical tab
rail, Acrylic-style window, PowerShell-first multi-shell discovery, and low
background overhead. Windows 10 / 11 x64. AGPL-3.0-only.

## Which file do I download?

**`Zinc-0.6.9-Setup.exe`** — the only installer. Per-user by default; no
administrator rights required for a normal install.

Other assets are the audit trail: `SHA256SUMS.txt`, `zinc-0.6.9.cdx.json`
(CycloneDX SBOM), `THIRD_PARTY_NOTICES-0.6.9.md`, `ASSET_PROVENANCE.md`,
`LICENSE`, plus `latest.yml` / `.blockmap` for the in-app updater.

## Zinc is not code-signed — verify before you run it

```powershell
Get-FileHash .\Zinc-0.6.9-Setup.exe -Algorithm SHA256
```

Compare against the line for `Zinc-0.6.9-Setup.exe` in `SHA256SUMS.txt` on this
page. Only if it matches: **More info → Run anyway**. If it does not match,
delete the file.

## What changed

Three fixes, all reproduced and verified against the running application.

- **A long IME composition no longer shoves the terminal off-screen.** Typing a
  long Pinyin composition pushed the whole pane to the left with the leading
  text cut off and no scrollbar to get back — only resizing the window restored
  it. xterm sizes its focused helper textarea to match the composition preview,
  which has no width limit, so the browser scrolled an ancestor to keep the
  caret in view. `overflow: clip` on the terminal stops that, where
  `overflow: hidden` could not.
- **Restoring a session no longer collapses several tabs onto one
  conversation.** `--continue` resumes the newest session *for a working
  directory*, but every Claude and Grok tab was given it unconditionally, so
  three tabs open in the same directory all reopened the same conversation.
  One tab per tool and directory now resumes; the others reopen as a plain
  shell in the right place.
- **Kimi Code is recognised.** It was missing from the detected-CLI list
  entirely, so those tabs were saved as "no tool" and never resumed.
- **Full-screen wheel paging applies to Kimi only.** The check tested for the
  alternate screen buffer and nothing else, so since 0.6.7 vim, less, htop and
  the Codex and Grok TUIs all had the wheel turned into PageUp/PageDown. They
  keep native line scrolling again.

Installer upgrade matrix is pinned to the reviewed public `v0.6.8` setup.
